# מכתבים לרבי

אפליקציית ווב (מותאמת לנייד ולמחשב, ניתנת להתקנה כאפליקציה – PWA) שבה כותבים מכתב לרבי בממשק בסגנון וואטסאפ.
בתשובה המערכת:

1. **פותחת את הספר במקום אקראי** (כמנהג הכנסת המכתב לכרך של אגרות קודש) – מתוך 11,062 האגרות שבכרכים א–כח ב[ספריית ליובאוויטש](https://chabadlibrary.org/books/1200000000), ומציגה **תמונה של העמוד** שנפתח: יכולים להופיע בו סוף אגרת קודמת, אגרות שלמות ותחילת האגרת הבאה.
2. מאפשרת להוריד את העמוד כ-**PDF**, ולפתוח כל אחת מהאגרות שבעמוד במלואה (טקסט ו-PDF, כולל ההערות).
3. אם האגרת **באידיש** (או בכל שפה אחרת משפת המענה) – מתרגמת לעברית או לשפה שהמשתמש בחר (ברירת מחדל: השפה שבה נכתב המכתב).
4. מציגה הסבר כיצד מה שנכתב במכתב עשוי לקבל התייחסות במענה.

אותו מנגנון חשוף גם כ-**API** וכ-**Webhook ל-WhatsApp Business (Cloud API)**.

## מסך הצ'אט

- **רשימת שיחות כמו בוואטסאפ:** מסך הבית מציג את השיחות (שם, המכתב האחרון, שעה, מספר מכתבים ו-★), עם חיפוש וכפתור ✎ לשיחה חדשה. שם השיחה נקבע לפי המכתב הראשון וניתן לשינוי.
- **לחיצה ארוכה על שיחה** (או ⋮ בתוך שיחה): שינוי שם, העברה לארכיון, נעילה ומחיקה.
- **בארכיון** ו**מועדפים:** שורות בראש הרשימה.
- **שיחות נעולות:** שיחה נעולה יורדת מהרשימה ומופיעה רק תחת "🔒 שיחות נעולות", שנפתחות בטביעת אצבע או בקוד המכשיר (באפליקציה: BiometricPrompt; בדפדפן: WebAuthn). יציאה מהאפליקציה נועלת אותן שוב. זו הסתרה מעיני מי שמחזיק את המכשיר, לא הצפנה.
- **בתוך שיחה:** מפרידי תאריך, ▾ לכיווץ מענה לשורה אחת, ☆ למועדפים עם תיאורים (מרגש, מדהים, מדויק… או משלך).
- **תמונת העמוד:** לחיצה מציגה אותה במסך מלא (לחיצות נוספות מגדילות). שם אפשר לדפדף לעמוד הקודם והבא בספר – בחצים או בהחלקה (`GET /api/page/<spec>/prev|next`). חזרה אחורה מציגה בדיוק את העמוד שממנו הגעתם.
- **מתחת לתמונה:** ההסבר, התרגום, הפעולות והאגרות מקופלים תחת כפתור אחד. שפת המענה נבחרת בתפריט השיחה (⋮).
- **האגרות בעמוד:** אזור מתקפל עם חצי דפדוף (הקודם מימין, הבא משמאל) והחלקה באצבע – גם מעבר לאגרות שבעמוד, לפי סדר הספר (`GET /api/igrot/<id>/prev|next`).
- **מרקר:** מסמנים טקסט באגרת, בהסבר או בתרגום ולוחצים על הכפתור הצהוב שמופיע למעלה; או "🖍 מרקר" – ואז כל סימון מודגש מיד. לחיצה על הדגשה מסירה אותה.
- **שיתוף:** טקסט המכתב עם תמונת העמוד.

כל אלה (שיחות, שמות, מועדפים, ארכיון, נעילה והדגשות) נשמרים במכשיר בלבד, ולא בשרת.

## חשבונות, סנכרון ושיתוף (Firebase)

- **התחברות עם Google** (👤 ברשימת השיחות): השיחות עוברות לחשבון ומסתנכרנות בין המכשירים. בלי התחברות הכול עובד כמו קודם, על המכשיר בלבד.
- **שיתוף שיחה** (⋮ ← "שיתוף עם אנשי קשר"): נוצר קישור `/join/<שיחה>.<קוד>`. מי שנכנס אליו ומתחבר מצטרף לשיחה, רואה את המכתבים והמענים ויכול לכתוב הודעות ולהגיב (↩) – אבל רק פותח השיחה כותב לרבי. פותח השיחה בוחר בין ✉️ מכתב לרבי ל-💬 הודעה למשתתפים. "הפסקת השיתוף" מסירה את המשתתפים ומבטלת את הקישור.
- **פרטי לכל מכשיר:** מועדפים, הדגשות, ארכיון ונעילה.
- **כללי האבטחה** נמצאים ב-`firestore.rules` ויש לפרסם אותם בקונסולה (Firestore ← Rules). הם נבדקים באמולטור: `npm run test:rules` (דורש firebase-tools ו-Java).
- המודול נבנה מ-`web/cloud.js` אל `public/vendor/cloud.js` ב-`npm run build:web`, ונטען רק כשצריך.
- באפליקציית אנדרואיד ההתחברות דורשת את `google-services.json` של הפרויקט (בהמשך).

## מקור האגרות

**איך נבנה העמוד:** במקור המקוון יש את טקסט האגרות אך לא את חלוקת העמודים של הספר המודפס, ולכן העמוד מדומה: נבחרת נקודה אקראית בתוך אגרת אקראית, העמוד מתחיל עד כאורך עמוד אחד לפניה (ואז עשוי להתחיל באמצע אגרת קודמת), ומנוע העימוד ממלא עמוד אחד בגודל עמוד ספר. לכן התוכן ורצף האגרות זהים לספר, אבל שבירת השורות והעמודים אינה זהה לדפוס. הערות השוליים אינן מוצגות בתמונת העמוד, אלא באגרת המלאה.

הטקסט נלקח מ-API של ספריית ליובאוויטש (`https://chabadlibrary.org/books/api/main?path=<id>`).
הקובץ `data/catalog.json` מכיל את מזהי כל האגרות (כרך ← מספר אגרת), ומשמש להגרלה. כדי לרענן אותו (אם נוספים כרכים באתר):

```bash
npm run catalog
```

**לימוד אורכי האגרות:** כל אגרת שהשרת מוריד (לכל משתמש) נמדדת, ואורכה נשמר בקובץ משותף לכל המשתמשים (`.cache/letter-lengths.json`, או הנתיב שב-`LENGTHS_FILE`). הידע נשמר גם אחרי הפעלה מחדש, ומצבו מוצג ב-`GET /api/stats`. כרגע ההגרלה עדיין נותנת לכל אגרת סיכוי שווה; הידע הזה מיועד לשקלול לפי אורך בהמשך (כמו בספר אמיתי), בלי הורדות נוספות. בשרת אירוח יש להפנות את `LENGTHS_FILE` לדיסק קבוע, אחרת הקובץ נמחק בכל פריסה.

> לפני העלאה לאוויר מומלץ לבדוק את תנאי השימוש של ספריית ליובאוויטש, ואם אפשר – לתאם איתם. השרת פונה לאתר רק לאגרת אחת בכל מכתב.

**בלי Claude:** אם אין `ANTHROPIC_API_KEY`, אין יתרה או שהשירות אינו זמין – העמוד, האגרות וקובצי ה-PDF מוחזרים כרגיל, בלי תרגום והסבר (`"explained": false`).

## API

`POST /api/letters`

```json
{ "letter": "טקסט המכתב", "replyLanguage": "he" }
```

`replyLanguage` אופציונלי (קוד ISO בן 2 אותיות). תשובה:

```json
{
  "id": "…", "volume": 15, "volumeHeading": "כרך טו",
  "title": "אגרות קודש, כרך טו, אגרות ה'שע, ה'שעא",
  "imagePath": "/api/answers/<id>/page.png",
  "pdfPath": "/api/answers/<id>/page.pdf",
  "letters": [
    { "number": "ה'שע", "startsOnPage": false, "endsOnPage": true,
      "pageText": "החלק שבעמוד", "fullText": "האגרת המלאה",
      "viewerUrl": "https://chabadlibrary.org/books/…", "pdfPath": "/api/answers/<id>/letters/0.pdf" }
  ],
  "sourceLanguage": "hebrew", "replyLanguage": "he",
  "translation": "…", "explanation": "…", "keyQuote": "…"
}
```

`GET /api/page/<spec>.png` – תמונת העמוד, `GET /api/page/<spec>.pdf` – העמוד כ-PDF, `GET /api/igrot/<id>.pdf` – אגרת מלאה. ה-spec מתאר את העמוד (כרך, אגרת ראשונה, מספר אגרות ונקודת התחלה), ולכן הקישורים תקפים תמיד – גם אחרי הפעלה מחדש של השרת.

## WhatsApp Business

1. יוצרים אפליקציה ב-Meta for Developers עם מוצר WhatsApp, ומעתיקים ל-`.env`:
   `WHATSAPP_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID`, `WHATSAPP_APP_SECRET`, ובוחרים `WHATSAPP_VERIFY_TOKEN`.
2. מגדירים `PUBLIC_BASE_URL` לכתובת HTTPS ציבורית של השרת (וואטסאפ מוריד את ה-PDF מכתובת זו).
3. כתובת ה-Webhook: `https://<השרת>/webhooks/whatsapp` (מנויים לשדה `messages`).

הודעת טקסט נכנסת ← אישור קבלה ← תמונת העמוד ← הודעה עם ציטוט, תרגום, הסבר וקישור ל-PDF.

## הערות

- המודל: `claude-opus-5-5` (ניתן לשינוי ב-`CLAUDE_MODEL`). מופעל fallback בצד השרת (`fallbacks: "default"`) כך שבמקרה של סירוב הבקשה ממשיכה במודל חלופי.
- ההסבר מוצג כהצעה להבנה בלבד ואינו פסק הלכה; ההנחיה למודל היא להתבסס רק על מה שכתוב באגרת.
- היסטוריית השיחה נשמרת רק במכשיר המשתמש (localStorage).

## פריסה ל-Render (חינם)

הקובץ `render.yaml` מגדיר שירות ווב בתוכנית החינמית, בלי דיסק קבוע.

1. ב-[Render](https://dashboard.render.com): New ← Blueprint ← לבחור את המאגר הזה.
2. להזין את `ANTHROPIC_API_KEY` כשמתבקשים (שאר המשתנים אופציונליים).
3. בסיום מתקבלת כתובת בסגנון `https://michtavim-larebbe.onrender.com` – זו כתובת השרת לאפליקציה, ואותה מגדירים גם ב-GitHub במשתנה `API_BASE_URL` כדי שתיכלל ב-APK.

מגבלות התוכנית החינמית:
- השרת נרדם אחרי כ-15 דקות בלי שימוש, והבקשה הראשונה אחר כך אורכת כדקה.
- אין דיסק קבוע: אורכי האגרות שנלמדו, ותמונות/קובצי PDF של תשובות קודמות, נמחקים בכל הירדמות או פריסה. כשיתווסף דיסק – להגדיר `LENGTHS_FILE`.

## אפליקציית אנדרואיד (APK)

תיקיית `android/` היא פרויקט Capacitor שעוטף את ממשק הצ'אט. האפליקציה פונה לשרת שכתובתו `API_BASE_URL`, ולכן קודם צריך להעלות את השרת לכתובת HTTPS ציבורית.

**בנייה אוטומטית ב-GitHub:** בכל push ל-`main` רץ ה-workflow `Android APK` ומעלה את הקובץ `app-debug.apk` ל-Artifacts של הריצה (לשונית Actions). את כתובת השרת מגדירים ב-Settings ← Secrets and variables ← Actions ← Variables, במשתנה `API_BASE_URL`.

**עדכון אוטומטי מתוך האפליקציה:** בכל push ל-`main`, אם מוגדר מפתח החתימה הקבוע, ה-workflow בונה APK חתום עם מספר גרסה עולה (מספר הריצה) ומפרסם אותו כ-GitHub Release בתגית `app-v<מספר>`. השרת מדווח על הגרסה האחרונה ב-`GET /api/app/latest` ומגיש אותה ב-`GET /api/app/download`. האפליקציה בודקת בפתיחה (ניתן לכבות), ובמסך ההגדרות (⚙) יש "בדיקת עדכונים" ו"הורדה והתקנה" – ההורדה וההתקנה נעשות מתוך האפליקציה.

הגדרת מפתח החתימה (פעם אחת) – ב-Settings ← Secrets and variables ← Actions ← Secrets:

| Secret | ערך |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | קובץ ה-keystore בקידוד base64 |
| `ANDROID_KEYSTORE_PASSWORD` | סיסמת ה-keystore |
| `ANDROID_KEY_ALIAS` | שם המפתח |
| `ANDROID_KEY_PASSWORD` | סיסמת המפתח |

> חשוב: Android מתקין עדכון רק אם הוא חתום באותו מפתח כמו האפליקציה המותקנת. **אין לאבד את קובץ ה-keystore ואת הסיסמאות** – בלעדיהם כל המשתמשים יצטרכו להסיר את האפליקציה ולהתקין מחדש. לעולם אין להכניס אותם ל-git. אם המאגר פרטי, יש להגדיר בשרת `APP_RELEASES_TOKEN`.

**בנייה מקומית** (דורש Android SDK ו-JDK 21):

```bash
API_BASE_URL=https://your-server.example npm run apk
```

הקובץ נוצר ב-`android/app/build/outputs/apk/debug/app-debug.apk`. זהו APK לניפוי שגיאות (debug) שניתן להתקין ישירות בטלפון. להפצה בחנות Google Play צריך לבנות גרסת release חתומה.
